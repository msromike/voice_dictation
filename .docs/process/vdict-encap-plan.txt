MEASURED 2026-08-04 -- STATIC DISCOVERY OVER vdict_tray.py
==============================================================================
AST-derived, not read by eye. Re-measured 2026-08-04 after P4a landed. The
load_settings and save_settings counts were re-derived after the stale-copy
fix landed in save_and_restart and on_close; nothing else here was re-run
then. Re-derive whatever figure the current step depends on rather than
trusting it -- an AST pass over one symbol is one command.

Counts are per innermost enclosing function. A pass that attributes a
nested function's references to its parent as well double-counts -- that
is how an earlier version of this section came to claim five save_settings
call sites instead of four.

STATE THAT CROSSES THE SPLIT
Attributes written by one function and read by another. Method lookups
excluded -- these are data, and each one is an edge some pair of new
modules has to carry.
  - settings_win -- set by _build_settings_window, read by
    _build_fault_modal and _confirm_bare_key. Two readers outside
    Settings.
  - _fault_shown -- set by __init__, _build_fault_modal and start_vdict;
    read by _update_output. Straddles the fault/subprocess line.
  - is_loading_model -- set by __init__, _drain_output_queue and
    start_vdict; read by _drain_output_queue. start_vdict resets console
    display state directly.
  - process, reader_thread -- set by start_vdict, read by _update_output
    and _stop_daemon.
  - hotkey_name, hotkey_failed -- set by _register_hotkey, read by
    _hotkey_line and _raise_window.
  - icon -- read by _drain_output_queue for toast dispatch. The console
    depends on the tray icon.
  - window (19 readers) and text (11 readers) are the two widest. Every
    text reader is a console concern except _save_log_as.

  - transcript_only_mode is NOT in this list. It is assigned once at
    module level and never rebound; there are no global statements
    anywhere in the file. It is a constant today.

scale
  - vdict/tray/dpi.py's scale() is called from 12 functions across what
    will become Settings, the fault modals and app. It is a leaf, so every
    one of those imports it directly and none of them creates an edge the
    wiring rule has to carry.

MODULE-LEVEL NAMES WITH CONSUMERS IN MORE THAN ONE PROSPECTIVE MODULE
  - DEVICE_LABELS -- Settings (_build_model_row, save_and_restart) and the
    session block (_log_session_block).
  - _format_bind -- Settings (_build_ptt_row) and _log_session_block.
  - _clamp_to_desktop -- Settings (open_settings) and run.
  - MIC_FAULT_FLAG_PATH -- _show_mic_fault and run.
  - PROJECT_URL -- _open_docs, _show_about, and run's banner.
  - __version__ -- _show_about and open_settings.
  - MB_ICONERROR -- _report_callback_exception and _log_startup_crash.
  - ICON_PATH -- __init__ and create_tray_icon.
  - load_settings has eight call sites (_build_hotkey_row,
    _log_session_block, _rebind_on_close, _save_console_state, on_close,
    open_settings, run, save_and_restart); save_settings has four
    (_save_console_state, on_close, run, save_and_restart).

IMPORT CYCLE
Two chains were traced. The first -- _drain_output_queue -> _show_mic_fault
-> open_settings -> _build_ptt_row -> _PTTCapture -> tray.log -- does not
close once log() lives in a leaf, because _PTTCapture then reaches the leaf
instead of the console.

The second does close, and the leaf does not help it: _drain_output_queue
-> _show_mic_fault -> open_settings -> save_and_restart -> restart_daemon
-> start_vdict, which sets is_loading_model and calls _log_session_block.
That is console -> faults -> settings -> daemon-subprocess -> console.
Every edge measured. This is what SKELETON's wiring rule exists to make
impossible rather than merely absent.

FAULT TRIGGERS
Both box-category faults are reachable without a test hook.
  - mic-fault -- audio.py's _exit_no_microphone, fired when the configured
    device is absent at startup or a stream open fails mid-session. Force
    it by naming a nonexistent device in config.json's audio.device. It
    ends in sys.exit(1) on the daemon side and a force-quit on the tray
    side, so the gesture costs a relaunch and consuming mic_fault.flag.
  - model-fault -- stt.py, both the constructor path and reload(), fired
    when WhisperModel() raises. SttConfig.model is a bare str with no
    Literal constraint, so a nonexistent model name passes pydantic
    validation and fails at load. Force it from config.json's stt.model.

PATH AND IMPORT HAZARDS
  - ICON_PATH and MIC_FAULT_FLAG_PATH are Path(__file__).parent.parent from
    voice-dictation/vdict_tray.py. Anything landing in vdict/tray/ needs
    four .parent steps, as common/config.py and common/output.py already
    use. ICON_PATH raises at launch if this is missed. MIC_FAULT_FLAG_PATH
    fails SILENTLY -- .exists() returns False on a wrong path, run() takes
    the else branch, and mic-fault recovery stops working with no symptom.
    start_vdict has the same trap twice: the vdict_daemon.py path and cwd.
  - SetProcessDpiAwareness runs at vdict_tray.py import and must precede
    both Tk root creation and any GetDpiForSystem call. Keeping it in the
    entry file satisfies this; a module-level DPI constant elsewhere would
    depend on import order and fail as blurry text, not an exception.
  - common/ is imported by both processes. Anything placed there executes
    in the daemon too. common/output.py already defines log() -- the
    daemon's stdout wire-format writer, imported by name and called 17
    times in vdict_daemon.py.
  - Four deferred imports are load-bearing and must move verbatim, not be
    hoisted to module level: pynput in _PTTCapture.start, sounddevice in
    _build_microphone_row, ctranslate2 in _has_cuda, and
    vdict.daemon.keyboard's BUTTON_MAP in _on_click -- a tray-to-daemon
    import that is only acceptable deferred.
  - voice-dictation\vdict_tray.py is hardcoded in vdict_run.bat,
    vdict_install.bat and startup_folder_install.bat, and named in
    README.md. Nothing imports it as a module. The path must survive; the
    contents can be emptied.

==============================================================================
SKELETON
==============================================================================
WIRING RULE
app.py is the only module that imports a wired module. Wired modules never
import each other; anything one needs from another arrives as a callable or
an object at construction. A LEAF is a module that imports no wired module
-- checkable by reading one import block -- and any module may import a
leaf.

What this beat: importing directly wherever the direction happens to be
acyclic. It does not happen to be acyclic (see IMPORT CYCLE), and whether
it is depends on facts four hops apart in the call graph, which nobody
re-verifies on every edit. The rule makes the cycle structurally
impossible and puts the whole dependency graph in one readable place. Cost
is constructor plumbing and app.py being the largest new module, because
assembly is its job.

LEAVES
  const.py           PROJECT_URL, ICON_PATH, MIC_FAULT_FLAG_PATH,
                     MB_ICONERROR, and the single Path base they derive
                     from. One home so the four-.parent math happens once
                     -- this is what stops the silent MIC_FAULT_FLAG_PATH
                     failure from being reintroduced by a moved module.
  dpi.py             scale(px) and the DPI read. Built by P4a.
  log.py             Owns the output queue. log() enqueues; error_log()
                     writes disk, then calls a screen-writer that console
                     installs.
  geometry.py        track(window, config_field), save_all(config),
                     _clamp_to_desktop, _geometry_parts.
  session.py         The session block. _summary_line, _human_size,
                     _model_size_on_disk, _format_bind, DEVICE_LABELS,
                     _hotkey_line. Stateless -- pid, config and hotkey
                     state arrive as arguments. A leaf because Settings
                     needs _format_bind and DEVICE_LABELS too, and a leaf
                     is the only tier both can import.
  ptt_capture.py     _PTTCapture.
  hotkey_capture.py  _capture_hotkey, _confirm_bare_key, _combo_name,
                     _vk_name, _windows_key_name, _state_to_mods, and the
                     key tables.
  hotkey.py          Exists. Unchanged.

WIRED -- imported only by app.py
  console.py         Output window: text widget, tags, context menu, zoom,
                     copy/clear/save-as, the queue drain and category
                     dispatch, loading animation, hide/unmap. Installs
                     log.py's screen-writer. Receives root, the tray icon
                     for toasts, and a fault-handler map.
  menu.py            Menubar, help sync, About, docs and error-log
                     openers. Receives root and a callback set.
  settings.py        The dialog, all row builders, save and close
                     handlers, rebind-on-close. Receives root and the
                     callables it fires (restart, hotkey re-register).
  faults.py          Shared modal builder plus the mic and model variants.
                     Receives root, an open-settings callable, a
                     settings-window accessor, and force-quit.
  icon.py            pystray icon construction. Receives callbacks.
  daemon_proc.py     Subprocess start/stop/restart, stdout reader, exit
                     poll. Reports through what it was handed rather than
                     setting is_loading_model itself. Deleted whole by
                     core-arch.
  app.py             The hub. Tk root, wiring, run(), exit and force-quit,
                     shutdown steps, the Tk exception handler, hotkey
                     registration, the tick.

ENTRY
  vdict_tray.py stays at its pinned path: platform guard, AUMID, the
  single-instance mutex, the startup-crash reporter, construct app, run.

COMMON
  common/config.py gains load_settings, save_settings, the healing
  machinery, and the vocabulary reseed.

CONSEQUENCES THAT ARE EASY TO GET WRONG
  - console does not import faults. app registers fault handlers into the
    console's dispatch.
  - restart_daemon reaches Settings as a callable, not an import.
  - app owns the 100ms tick: console.drain(), then the subprocess exit
    poll, then reschedule. Core-arch deletes one line and the tick becomes
    console-only.
  - Settings imports ptt_capture and hotkey_capture directly. Both are
    leaves, so this is allowed and creates no cycle.


==============================================================================
DECISIONS 2026-08-04
==============================================================================
CODE CORE-ARCH WILL DELETE
Sorted by fate, not by category. Subprocess management (start_vdict,
_read_output, _stop_daemon, restart_daemon, _run_shutdown_steps) goes into
one module with a deliberately minimal surface, which core-arch deletes
whole; _read_output is a queue producer, so core-arch swaps producers
without touching the console. Config load/heal (load_settings,
save_settings, _reseed_vocabulary_if_missing, FIELD_LABELS,
_delete_at_path, _format_value, _wholesale_reset_message,
_summarize_config_error) relocates verbatim into vdict/common/config.py,
no consolidation and no signature changes -- where core-arch's own
migration will happen anyway. What this beat: leaving both in the entry
file, which forces every extracted module that calls load_settings to
import the entry file that imports them back.

WINDOW GEOMETRY
Registry, not one-off per-window save calls -- track(window,
config_field), one save_all(config). Flushed at exit AND at hide, keeping
today's two trigger points, not exit only. What exit-only beat: nothing --
it loses everything since the last clean exit for anyone who quits via
Task Manager or a Windows shutdown, which is a larger loss than the
unsaved-drag-on-crash case that entry accepted. track() needs a <Destroy>
hook that captures a window's final geometry into the cache, because
Settings is a transient Toplevel destroyed long before exit; without it
settings_pos is silently dropped.

The point of the registry is that a new window is covered by one track()
call rather than a shutdown-step edit someone has to remember. Anything
that replaces it with per-window save calls has undone the reason it
exists, however tidy it looks.
  -> core-arch-plan.txt's CONFIG PERSISTENCE bullet ("Written at
     checkpoints -- Save, window hidden, geometry settled") needs a pass
     against this.

log() AND error_log()
Both live in log.py, split by whether the call can be asynchronous.
  - log() enqueues. Callers import the leaf; nothing threads a console
    reference.
  - error_log() writes disk first, then calls the screen-writer console
    installs -- synchronously, never through the queue.
    _report_callback_exception calls it, then a native MessageBoxW, then
    _force_quit; MessageBoxW blocks with no Tk event loop, so a queued
    item written there would never reach the screen. The disk write
    happens whether or not a screen-writer has been installed yet.
  - Not placed in common/output.py: the name is taken by the daemon's
    wire-format log(), and freeing it means editing 17 out-of-scope call
    sites. Core-arch deletes the wire format when the processes merge,
    which frees the name at no cost.

dpi_scale
Gone. P4a retired it -- vdict/tray/dpi.py owns the DPI read outright and
every scaled dimension goes through its scale(px). No module holds a DPI
value, app included, so nothing receives one at construction. scale()
reads lazily and caches, which is what keeps it from running before
SetProcessDpiAwareness; a module-level constant would not.
Fonts never go through scale() -- Tk already scales point sizes by DPI.
Two comments in the code say so at the point of temptation.

__version__
Tray side reads vdict/__init__.py's copy. The entry file's own copy dies
with the gutting; nothing carries it into a new module. vdict/__init__.py's
no-re-exports warning is about import weight and does not apply to a str
already living there. vdict_daemon.py's copy is out of scope -- backlog
B25.


==============================================================================
VERIFICATION
==============================================================================
Every step ends with a launch and only the gesture that step's code owns.
One full gesture sweep at the end of the sheet. Steps are vertical slices
-- extract, rewire callers, delete the original, all inside one step --
never move-then-rewire, so stopping at any boundary leaves a working app.

Fault-modal steps force the real condition from config.json rather than
injecting a category. See FAULT TRIGGERS above for what to write, and
CLAUDE.md's BAK AND RESTORE for the config handling that goes with it.
What a test hook would have beaten: nothing -- injecting into the queue
skips the daemon emitting, stdout carrying, and output.parse splitting,
which is three of the four things these steps are checking.
