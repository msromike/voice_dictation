VOICE DICTATION - PLAN: AUDIO DEVICE HANDLING

Reference material for build-v2-build-sheet.txt -- the governing rule, the
full error classification, the spec conditions, and what was already tried
and abandoned. Read this to understand WHY build-v2-build-sheet.txt's steps
say what they say; that sheet itself carries only the actions.

Extracted 2026-07-31 from build-v2-build-sheet.txt (then named build-v2.txt),
verbatim except for one correction (ERROR CLASSIFICATION's Tier B, marked
below) -- no new narrative added.


==============================================================================
GOVERNING RULE
==============================================================================
THERE IS NO RESUME FOR THE MICROPHONE. A microphone failure ends the process.
The app never falls back to another device, re-resolves, or recovers in place.

SCOPE. Microphone acquisition ONLY. A failed transcription, a blocked paste
or a missing model do NOT end the process -- see the classification below.
Applied everywhere, this rule would kill the app over one bad dictation.

If a step appears to need a microphone fallback, a retry, a watchdog or a
device-change callback, the step is wrong.


==============================================================================
ERROR CLASSIFICATION
==============================================================================
The axis is not known vs unknown. It is: does it clear itself, and can the
user do anything about it.

  clears itself?   user can fix?   action
  yes              n/a             stay silent
  no               in Settings     open Settings, modal names it
  no               outside app     output window + traceback, modal, tray alive
  transient        n/a             one output line, keep running

TIER A -- MICROPHONE. Settings as SIGNAGE, modal, Close, APP EXITS, flag.
  A1  configured mic absent at launch
  A2  configured mic absent at PTT
  A3  no capture devices at all
  A4  mic held exclusively by another app -- open throws -9992

TIER B -- MODEL / COMPUTE. Settings INTERACTIVE, modal, TRAY ALIVE, no flag.
  B1  model download fails -- no network, disk full
  B2  model name invalid
  B3  CUDA requested, unavailable -- message says switch to CPU
  All three route through STTEngine.load's except block, which calls
  log("model-fault", text) then sys.exit(1) -- corrected 2026-07-31, was
  "the RuntimeError already raised in STTEngine.load... nothing catches
  it," stale since output-logging's own 5h removed the raise entirely.
  Changing the model and reloading ALREADY WORKS -- do not break it by
  exiting the app.

TIER C -- NOT FIXABLE IN SETTINGS. Output window + traceback to front, modal,
          tray alive, restart offered, NO FLAG.
  C1  missing Python deps ......... KeyboardInjector has the message
  C2  config.json missing ......... load_config has the message
  C3  vocabulary.txt missing ...... _load_vocabulary has the message
  C4  config.json invalid JSON .... load_config() raises RuntimeError
                                    naming the file and the problem
                                    (built 2026-07-31, build-v2-defects
                                    item F) -- still an uncaught crash,
                                    just a readable one; no dispatch bundle
                                    (traceback to front, modal, restart
                                    offered) yet.
  C5  config.json missing a key ... same as C4 -- both route through the
                                    same pydantic.ValidationError catch.
  C6  PTT listener fails to start
  C7  any unhandled exception
  C8  daemon killed externally

TIER D -- PER DICTATION. One output line, session continues.
  D1  recording too short ......... built
  D2  no speech detected .......... built
  D3  toggle-mode timeout ......... built
  D4  transcription throws ........ NEW. Currently kills the daemon.

  DROPPED: device pulled mid-recording. Truncated text, no message.

TIER E -- SILENT BY DESIGN. Do not add logging to these.
  E1  GPU primer thread fails ..... warm-up only
  E2  clipboard read fails ........ defaults to ""

CROSS-REFERENCE: output-logging-categories-results.csv uses different tier
vocabulary for the same concepts -- "intervention" (Tier A/B, confirmed for
the mic-fault row; model-fault grouped with it by the same SEVERITY TIERS
document, not independently confirmed by its own CSV row), "unanticipated-
exception" (confirmed, the Tk-callback row), "cannot-even-start" (confirmed,
the startup-crash row). Same concepts, different names, not a contradiction.


==============================================================================
THE SPEC -- 13 CONDITIONS
==============================================================================
AT LAUNCH
  L1  named device present ................. start normally
  L2  named device absent .................. FAIL
  L3  System Default, one exists ........... start normally
  L4  System Default, none exists .......... FAIL

AT PTT PRESS
  P1  device still present ................. resolve, open, beep, record
  P2  device unplugged since launch ........ FAIL
  P3  device held exclusively by other app . FAIL
  P4  stale index, device renumbered ....... Not seen in 38 cycles. A stale
                                             index carries the WASAPI endpoint
                                             id, so it resolves correctly or
                                             throws -9992.

DURING RECORDING
  R1  device stays connected ............... normal dictation
  R2  device pulled mid-recording .......... truncated audio, ACCEPTED

ANY TIME
  X1  any unhandled exception .............. try/finally cleanup, clean exit
  X2  launch with the failure flag set ..... open Settings, interactive
  X3  recovery launch must NOT re-FAIL ..... suppress the exit, or the user
                                             loops and never reaches Settings

FAIL is ONE handler, used by L2, L4, P2 and P3:
  name does not resolve, or the open throws
    -> tray opens Settings as SIGNAGE, not interactive
    -> modal on top, names the missing device, one Close button
    -> user clicks Close
    -> whole app exits, daemon and tray
    -> flag written


==============================================================================
WHAT WAS TRIED AND ABANDONED
==============================================================================
Recorded so nobody rebuilds it. All measured on the dev box 2026-07-26.

  fallback chain to system default ... lands on webcam mics and empty line-in
                                       jacks. Records silence.
  re-resolve every capture .......... reads a frozen list. Heals nothing.
  pycaw change listener ............. notification without refresh is
                                       useless; refresh alone is enough.
  _terminate/_initialize refresh .... unnecessary once there is no resume.
  live dropdown refresh ............. tray enumerates fresh at open.
  soundcard / miniaudio ............. replace a working capture path to fix
                                       an adjacent bug. soundcard also has an
                                       open mono-capture bug.
  stop/close exception guards ....... they do not throw. Measured.
  moving the start tone after the
  stream opens ...................... open is 0.015s live, 0.000s failing.
                                       There is no gap to talk into.
