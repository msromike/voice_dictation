STEP 2  vdict/devices.py -- ONE COPY OF THE DEVICE RULES
==============================================================================
PRECONDITION
  [ ] Every box in STEP 1 is [x]. Stop and close it if not.

Both processes must agree. The tray writes a device name into config.json and
the daemon matches it. If the two filter differently by even one condition,
the tray writes a name the daemon can never match and the user gets
"Microphone Not Available" for a microphone that is plugged in and working.

  [ ] 2a  NEW FILE. One WASAPI host-api lookup and one capture-endpoint
          filter, used by both callers.
  [ ] 2b  list_input_devices() -> names of connected WASAPI capture
          endpoints. The tray dropdown uses this.
  [ ] 2c  resolve(name) -> index. Full-name match, WASAPI only, no fallback.
          The daemon uses this.
  [ ] 2d  Empty name means System Default: the WASAPI default input. No
          default present is L4, which FAILs.
  [ ] 2e  Raise the WASAPI-missing error here, moved out of open_settings:
          "Windows WASAPI audio backend not available. The sounddevice
          install is incomplete -- rerun vdict_install.bat."
          It currently exists only in the tray; the daemon fails obscurely.
          Tier C.
  [ ] 2f  The tray imports this LAZILY, inside open_settings. It already
          defers `import sounddevice` there. A module-scope import regresses
          tray startup.

  RULES THAT ARE EASY TO GET WRONG
  - Pass the INTEGER index to sd.InputStream, never the name. sounddevice's
    own matcher walks every host api and matches on "name, hostapi", so "PDP"
    can resolve to the MME or DirectSound entry.
  - Do NOT normalise or strip the configured name. The real string is
    "Microphone (USB Audio CODEC )" -- trailing space before the paren.
  - Compare full names, not substrings.

  VERIFY
  [ ] 2g  list_input_devices() matches a fresh process's WASAPI capture
          list -- Claude runs via a standalone script, no app launch.
  [ ] 2h  resolve("no-such-device") returns None. It does not raise and it
          does not fall back -- Claude runs via the same script.
  [ ] 2i  Importing devices.py opens no stream and touches no hardware --
          Claude confirms via the same script (import alone, check no
          stream object exists).

  No live app needed for any of this step's VERIFY -- devices.py is
  self-contained. Claude's own work throughout.
