VOICE DICTATION - BUILD SHEET: PORTABLE FOLDER

ON THE FLY
  WHY THIS SHAPE
  The model and the Python interpreter are the only two things the app needs
  that live outside its own folder. Pull both inside and the installed folder
  becomes the distributable -- copy it anywhere, hand it to anyone, nothing to
  install. No plan owns this; the Qt port changes packages, not destinations.

Done = the folder, copied elsewhere with userdata left behind, launches and
transcribes while C:\bin\PortableTools\Python312 is renamed away.

==============================================================================
GOVERNING RULE
==============================================================================
Everything the app needs at runtime lives inside the folder and is found by a
path relative to the folder itself. Nothing is read from a user profile, a
system cache, or any absolute path outside the tree. Qt does not change this
and neither does anything after it.

==============================================================================
  [ ] 1a  Set HF_HUB_CACHE to <root>/models in vdict_tray.py, above the App
          import and beside the SetProcessDpiAwareness call. NOT HF_HOME --
          measured: that one adds a hub/ level underneath, and session.py's
          cache lookup reads HF_HUB_CACHE first regardless. One site:
          daemon_proc's env starts from os.environ.copy(), so the subprocess
          inherits it.
  [ ] 1b  Add models/ to .gitignore.
  [ ] 1c  COPY every cached Systran/faster-whisper-* snapshot from the profile
          cache into models/. All of them, not only the configured one:
          Settings offers every size, and a dropdown whose other choices need
          an internet connection is worse than a larger folder. Size is not a
          constraint here -- re-derive it rather than trusting a figure.
          Copy, never move -- the profile copy is the fallback until the
          gesture below passes, and CLEANUP deletes it, not this step.
          No link handling needed anywhere downstream: measured on this
          machine, every cached file is a real file, the blobs directory
          holds nothing, and nothing is a symlink or a hardlink. stt.py's
          comment claiming HuggingFace does it both ways is not what this
          cache actually does.
  [ ] 1d  stt.py load() tells the user to pick a different
          model or switch to CPU. That is wrong advice when nothing is on
          disk to load. Split the message: name a missing model separately
          from a device that cannot run it.
  [ ] 1e  Pass local_files_only=True to WhisperModel. A shipped folder
          carries its models; a download attempt on a recipient's machine is
          always a packaging failure, and failing immediately says so. This
          is what makes 1d's missing-model message reachable instead of
          hypothetical.
          Consider download_root as well -- it sets the model directory as an
          explicit argument rather than through a process-wide environment
          variable. Same destination as 1a, narrower blast radius. Pick one;
          do not set both and leave a reader guessing which wins.
  [x] 1f  PRIVACY, and it blocks the handoff. FLAC_CORPUS_CAPTURE_ENABLED is
          a constant set True in vdict_daemon.py, and source ships. A stick
          handed to anyone starts recording their voice to disk on first use.
          The code comment says it goes off "before any push" -- handing
          someone a USB stick is not a push, so that gate never fires.
          Fix: dev-flags.toml at the repo root, starting with one entry,
          capture_corpus. AN ABSENT FILE MEANS EVERY FLAG IS OFF -- the
          file's existence is the master switch and the capture branch never
          runs without it.
          BUILT: vdict_daemon.py reads capture_corpus from dev-flags.toml into
          FLAC_CORPUS_CAPTURE_ENABLED at import. The rest of this item is the
          definition, and stays here.
          It travels by neither route: gitignored, and not on copy_usb.bat's
          include list. Name it once, here -- the daemon, .gitignore and the
          copy list all have to agree, and three sites inventing three
          spellings is how this silently stops working.
          TOML rather than INI or JSON: pyproject.toml already makes TOML a
          format in this tree and INI is not, tomllib is stdlib on 3.12, and
          it yields real booleans instead of strings to coerce. tomllib is
          also READ-ONLY, so the app cannot rewrite this file by
          construction -- the opposite of config.json, which gets rewritten
          on every Settings close.
          NOT a config field. Dev tooling, not a user setting; in config.json
          it would read as an option someone is meant to choose.
          DEV FLAGS ONLY. transcript.ENABLED and console.transcript_only_mode
          are unfinished FEATURES waiting on Settings UI, not dev tooling,
          and they stay where they are. Mixing them in means this file never
          empties and nobody can tell which entries are temporary. B24's
          ambient retention flag is the second entry, when it comes.
          MALFORMED FILE CRASHES, absent file does not. The asymmetry is
          deliberate: absence is the normal shipped state, so it must be
          silent, while broken syntax is a developer's typo on a developer's
          machine and must be loud. tomllib raises; let it. Swallowing it and
          running with flags off is the worst outcome available -- you would
          believe capture was on and be building nothing.
          Honest limit: dragging the WHOLE tree by hand carries the file,
          exactly as it would carry a userdata folder. Nothing defends
          against copying everything, and it is not worth designing for.
          pre-push.txt names FLAC_CORPUS_CAPTURE_ENABLED by symbol and goes
          stale the moment this lands. Repointing it belongs to whichever
          step writes the file -- a pre-push gate naming a constant that no
          longer exists is a gate that silently passes.

  [ ] 4a  Write copy_usb.bat at the root. It takes a destination PATH as an

  [ ] 4b  PRE-FLIGHT, before any destination check: models/ holds a model and

  [ ] 4c  Name every folder it copies. An include list, never everything-
          minus-exclusions: the failure mode of an exclude list is shipping
          userdata, which holds voice recordings and the dictation history
          database. That is the copier's own voice on the first hop and the
          recipient's on every hop after -- the list protects whoever runs
          it, not only Mike. Add README.md, LICENSE and
          startup_folder_install.bat -- the recipient wants all three and
          they cost nothing.
          copy_usb.bat COPIES ITSELF. 4h ships a README pointing at it, so
          leaving it behind hands the recipient instructions for a script
          they do not have -- and the folder they drag by hand instead
          carries their own recordings. Every copy can make a clean copy.
          Scope: the include list governs which top-level folders ship at
          all. Excluding a subfolder of one that is already shipping is a
          different thing and stays allowed -- see 4l.
  [ ] 4d  Refuse a destination inside this tree, and refuse the tree root
          itself. Either one copies the folder into itself.
  [ ] 4e  Create the destination folder when it does not exist. An unmounted
          drive stops the script before anything is copied.
  [ ] 4f  Check free space on the destination's own volume against the size
          of the set, before copying starts. Failing three gigabytes in is a
          long wait for an answer available at the beginning.
  [ ] 4g  robocopy, not xcopy -- venv nests deeper than xcopy handles. Exit
          codes 8 and above are failure; 0 through 7 are normal success, and
          reading any non-zero as failure is the easy way to get this wrong.
  [ ] 4h  Record in README.md how to hand the folder to someone, pointing at
          copy_usb.bat for the set. The script is the one authority, or the
          list drifts in two places.
  [ ] 4i  Removable-media guard on vdict_run.bat, vdict_install.bat and
          startup_folder_install.bat. All three, one prompt: continue from
          the stick, copy to a local path first, or exit. Continue always
          stays available -- running from the stick is the capability being
          proven, and it is slow, not broken. The prompt says so, or the
          user reads a long model load as a hang.
  [ ] 4j  Copy-to-local calls copy_usb.bat rather than growing a second copy

  [ ] 4k  copy_usb.bat gets NO removable-media guard of its own. Deliberate,

  [ ] 4l  Decide whether venv\Scripts belongs in the copy set. After Step 2
