VOICE DICTATION - BUILD SHEET: SPLIT vdict_tray.py (P4)

Design lives in vdict-encap-plan.txt. This sheet does not repeat it -- read
SKELETON and DECISIONS there before starting, and treat the plan as the
authority if the two ever disagree.

Done = vdict_tray.py holds only the entry point, every piece named in the
plan's SKELETON is its own module, and the app behaves as it does today.

ORDERING RULE: riskiest first. The only thing here that can genuinely fail
is the wiring rule holding against the measured cycle (console -> faults ->
settings -> daemon-subprocess -> console). Steps 1-3 exist because the
console cannot be extracted without them, not to bank easy progress. The
cycle is exercised at step 4. Pure leaf relocations come last, so stopping
early is harmless.

EVERY STEP IS A VERTICAL SLICE: create the module, move the code, rewire
every caller, delete the original -- all inside the step. Never move in one
step and rewire in the next. Every step ends with a launch and only the
gesture that step's code owns, plus a commit. Full sweep at the end.

==============================================================================
STEP 1  log.py -- THE LEAF EVERYTHING REPORTS THROUGH
==============================================================================
Nothing else can move first: every module extracted later calls log() or
error_log(), and both live on the tray object today.

  [ ] 1a  Create vdict/tray/log.py. Owns the output queue outright.
          log(category, text) enqueues. error_log(context, text) writes
          disk via common.output.write_error_log FIRST, then calls an
          installed screen-writer if one exists -- synchronously, never
          through the queue. install_screen(fn) registers that writer.
          The disk write happens whether or not a writer is installed.
  [ ] 1b  vdict_tray.py installs a screen-writer that inserts into
          self.text, replacing the body of the old error_log method.
  [ ] 1c  Rewire every self.log() and self.error_log() call site to the
          module functions, and delete both methods. _PTTCapture's
          self.tray.log/self.tray.error_log calls go too.
  [ ] 1d  The drain reads log.py's queue instead of self.output_queue.

VERIFY: launch. Session block prints with correct colors and markers.
Trigger an error_log path -- rebind PTT and press a key pynput cannot name,
or force model-fault -- and confirm the error log file gets the entry AND
the console shows it.


==============================================================================
STEP 2  common/config.py -- LOAD AND HEAL
==============================================================================
Ordering: must precede Settings, the session block and geometry. All three
call load_settings, and if it is still in vdict_tray.py when they move out,
each new module has to import the entry file that imports it back.

  [ ] 2a  Move load_settings, save_settings, FIELD_LABELS, _format_value,
          _delete_at_path, _wholesale_reset_message,
          _summarize_config_error and _reseed_vocabulary_if_missing into
          vdict/common/config.py. Verbatim -- no consolidation, no
          signature changes. The daemon's existing load_config and
          load_vocabulary stay untouched; merging them is core-arch's job.
  [ ] 2b  Rewire all six load_settings and four save_settings call sites,
          plus VOCABULARY_RESET_MESSAGE.

VERIFY: launch. Settings opens with current values, Save persists them,
console geometry survives a hide and restore. Delete userdata/config.json
first on a second launch to confirm the reseed path still writes defaults
and logs the reset lines -- BAK AND RESTORE per CLAUDE.md.


==============================================================================
STEP 3  geometry.py -- THE REGISTRY
==============================================================================
This is the one step that changes behavior rather than relocating it. See
the plan's WINDOW GEOMETRY.

  [ ] 3a  Create vdict/tray/geometry.py: track(window, config_field),
          save_all(config), plus _clamp_to_desktop and _geometry_parts
          moved verbatim.
  [ ] 3b  track() caches live geometry on <Configure> while the window is
          in normal state, and binds <Destroy> to capture a final position
          into the cache. Without the <Destroy> hook, Settings is torn down
          before exit and settings_pos is silently dropped.
  [ ] 3c  save_all(config) writes every cached entry. Called at exit and at
          hide -- both of today's trigger points, not exit only.
  [ ] 3d  Console window and Settings both register through track().
          _remember_geometry, _save_console_state's geometry half, and
          Settings' two _get_pos writes all go away.

VERIFY: launch. Move and resize the console, hide to tray, restore -- size
and position kept. Move Settings, close it, reopen -- position kept. Exit
and relaunch -- both kept. Then confirm a window closed but not exited
still persists: move Settings, close it, exit without reopening, relaunch.


==============================================================================
STEP 4  console.py -- THE CYCLE STEP
==============================================================================
The risk this whole ordering exists for. console must NOT import faults.
app registers fault handlers into the console's dispatch, so the measured
cycle has no edge to close on.

  [ ] 4a  Create vdict/tray/console.py. Owns the text widget, color tags,
          context menu, zoom and font sizing, select/copy/copy-all/clear,
          save-log-as, the queue drain and category dispatch, the loading
          animation, and hide/unmap. Installs log.py's screen-writer.
  [ ] 4b  Constructor takes the Tk root, the tray icon (for toasts), a
          handler map for box-category dispatch, and a save-state callable
          it invokes on hide. At this step app populates the handler map
          with the fault methods still living in the tray class -- they
          move out in step 5.
  [ ] 4c  transcript_only_mode, _swallow_set, COLOR_TAGS, CONSOLE_FONT_*
          and the transcript logger move with it.
  [ ] 4d  Delete every console method from the tray class.

VERIFY: launch. Console shows output with correct colors. Ctrl+scroll and
Ctrl+0 zoom. Copy, Select All, Copy All, Clear. Save As writes a file. Hide
to tray and restore. Force model-fault -- the modal must still appear,
which is what proves the handler map works. Minimize to confirm unmap still
hides rather than iconifies.

==============================================================================
  [ ] 5a  Create vdict/tray/faults.py with the shared modal builder and the

==============================================================================
STEP 6  settings.py
==============================================================================
The most entangled piece. settings_win is read from outside by the fault
modals and by the bare-key confirmation.

  [ ] 6a  Create vdict/tray/settings.py: the window builder, all five row
          builders, the hotkey row, the save handler, on_close, and
          _rebind_on_close.
  [ ] 6b  Receives the Tk root and the callables it fires -- restart, and
          hotkey re-register. It does not import daemon_proc.
  [ ] 6c  Exposes the live window so faults.py can parent to it, through
          whatever app hands faults in 5a rather than a direct import.
  [ ] 6d  sounddevice stays imported inside _build_microphone_row, pynput
          inside the PTT capture, ctranslate2 inside _has_cuda. Hoisting
          any of them to module level drags heavy dependencies into tray
          startup.

VERIFY: launch. Open Settings from the tray menu and from File. Change each
control and Save -- values persist and the daemon restarts. Escape closes.
Close and reopen from the fault path. Rebind the output-window hotkey,
close Settings, confirm the new hotkey works -- that is _rebind_on_close.


==============================================================================
STEP 7  daemon_proc.py
==============================================================================
Core-arch deletes this module whole. Keep its surface minimal; do not give
it a polished API it will never need.

  [ ] 7a  Create vdict/tray/daemon_proc.py: start, stop, restart, the
          stdout reader thread, and the exit poll. _exit_reported and
          _fault_shown move with it.
  [ ] 7b  It must not set console state directly. Today start_vdict assigns
          is_loading_model -- that becomes a call on whatever app hands it,
          which is the edge that closed the measured cycle.
  [ ] 7c  app owns the 100ms tick: drain the console, then poll the
          subprocess for exit, then reschedule. Core-arch later deletes the
          second call and the tick becomes console-only.

VERIFY: launch. Session block prints with the daemon PID. Save & Restart in
Settings swaps the daemon and reprints the block. Kill vdict_daemon.py from
Task Manager -- the console reports the exit code once, not repeatedly.
