VOICE DICTATION - PARITY INVENTORY

Everything a user can reach today. Derived from source, never from memory of
using the app. This is what pass-1 parity is checked against -- not the
implementation, since reproducing a Tk accident is not parity.

Read against this, do not maintain it by hand. Where a set could drift, the
line says how to re-derive it.

Consumed by: qt-port-plan.txt DELIVERABLES (defines parity), and its
SCRATCHPAD item that reads Qt's module surface against this list.

Accelerator text is display only in Tk. Every one above is bound separately,
so a label can disagree with what the key actually does. Re-derive the true
bindings from the bind() calls, never from the accelerator strings.

DIALOGS AND THEIR BUTTONS
==============================================================================

                           Not resizable. Placed bottom-right on first open
  About                    OK
  Already running          OK -- its own throwaway Tk root in vdict_tray.py,
                           separate from the app's
  Exit confirmation        OK / Cancel
  Shutdown failure         OK -- only when a shutdown step threw

  Callback exception       OK -- native MessageBoxW, because Tk may be what

==============================================================================
PUSH-TO-TALK -- the product. IN SCOPE, not out
==============================================================================
Lives in the daemon process, but the tray owns its configuration and its
capture UI, and the two share a vocabulary. See COUPLING below.

  Hold mode        press and hold to record, release to stop
  Toggle mode      press once to start, press again to stop. Times out on
                   its own -- re-derive the limit from the wait_for_press
                   timeout in vdict_daemon.py
  Trigger          a mouse button, or any key stored as "key:<name>".
                   Re-derive the accepted mouse names from BUTTON_MAP.
                   LEFT IS DELIBERATELY ABSENT -- it would record on every
                   click
  Too short        a capture under the minimum sample count is discarded
                   with a tone and a note, never transcribed. Re-derive the
                   threshold from MIN_RECORDING_SAMPLES
  Tones            start, stop, timeout, too-short and ready are distinct.
                   All are silenced by the beeps checkbox; the ready console
                   line and its toast still appear
  Delivery         transcript is placed on the clipboard and pasted at the
                   cursor with a synthesised Ctrl+V, with a trailing space
                   added. The previous clipboard is restored unless
                   preserve_clipboard says otherwise
  Console          [REC] on start, the bare transcript, [DONE] on finish
  GPU              a primer transcription fires on press when the device is
                   cuda, to spool the GPU while the user is still talking


==============================================================================
BEHAVIOURS WITH NO MENU ENTRY
==============================================================================
  Minimize goes to the TRAY, not the taskbar
  The X button exits the application, after confirmation
  The global hotkey raises and focuses the output window from anywhere
  First run opens Settings by itself, shortly after launch
  Mic-fault recovery SPANS TWO LAUNCHES: the modal writes a flag and quits,
    and the next launch reads it, prints a note, opens Settings, and does
    NOT start the daemon
  Window position, size and maximized state persist. So does console font
    size
  A startup banner prints once per launch, never on a daemon restart
  A session block prints on every daemon start, including restarts
  The loading animation appends dots on its own timer while a model loads
  Config repairs itself field by field and names in the console whatever it
    reset


==============================================================================
COUPLING THE REBUILD MUST PRESERVE
==============================================================================
  tray/ptt_capture.py imports BUTTON_MAP from vdict/daemon/keyboard.py. The
    tray reaches directly into the daemon's module
  config.ptt.button strings are WRITTEN by the tray's capture and PARSED by
    the daemon's PTTListener. A capture that emits a different string breaks
    dictation with nothing in the console to explain it
  config.audio.device is matched by the daemon as a NAME SUBSTRING, not an
    identifier
  The daemon talks to the tray in one wire format, "category|text", parsed
    by output.parse. Categories carry colour, marker, box and toast flags
