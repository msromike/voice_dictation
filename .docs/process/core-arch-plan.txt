==============================================================================
LIVE-READ SETTINGS (no reconfigure entry point)
==============================================================================
  - main() reads config once at startup and nobody re-reads config.json
    again, which is why every change needs Save & Restart today. This
    section is what replaces that. Hoists gone -- CaptureSession reads
    config at point of use.
  - The orchestrator holds one live Config instance for the whole process
    lifetime. The Save handler mutates its fields in place -- it never
    replaces the object with a new instance. Every thread needing a live
    value holds a reference to that same object, not a copy.
  - Consumers read the field directly, at the point of use, every time --
    play_tone() reads the live value right where it's called. No entry
    point, no flag, nothing to call.
  - Safe without a lock: attribute get/set on a shared object is atomic
    under the GIL.
  - Inventory (B1's CONFIG RE-READ tier): vocabulary.txt, audio.feedback,
    ptt.mode, keyboard.preserve_clipboard.
  - Persistence is still the Save handler's job, same checkpoint
    mechanism as CONFIG PERSISTENCE -- mutating the field live doesn't
    write it to disk by itself.
  - vocabulary.txt specifically: parsed fresh on every PTT cycle, not
    hoisted once like today's prompt = load_vocabulary() before the
    loop. Every successful read also copies what was just read into
    vocabulary.txt.bak -- costs the same as the read itself.
  - Recovery priority if vocabulary.txt is missing at read time: restore
    from vocabulary.txt.bak if it exists (preserves curated words), else
    reseed from the template. Either way, log a note -- never silent.
  - The reseed-if-missing logic consolidates into one shared helper in
    vdict/common/config.py, replacing two separate implementations that
    only existed because tray and daemon used to be different processes
    (common/config.py's reseed_vocabulary_if_missing, which copies from the
    template, and load_vocabulary()'s current raise-if-missing). Both the
    tray's boot-time reseed and File > Vocabulary's reseed become thin
    callers of the same function the live-read path uses.


==============================================================================
MODEL RELOAD / AUDIO DEVICE
==============================================================================
COMMON TO BOTH
  - Two-entry-point pattern (see ARCHITECTURE): STTEngine gets
    reload(config) alongside its existing transcribe()/wake_gpu();
    AudioCapture gets rebuild(config) alongside start_capture()/
    stop_capture(). Two real methods per class, not a branch inside one --
    different names on purpose, so "reload" always means the model and
    "rebuild" always means the device.
  - Orchestrator calls both reconfigure entry points unconditionally,
    every time Settings returns -- not gated on the orchestrator
    detecting a change itself. Whether real work happens is each
    method's own decision.
  - One shared flag protects the PTT loop's single gate -- don't start a
    new cycle. reload(), rebuild(), or a cycle's own pending-delivery
    confirmation can each set it before starting real work; whichever set
    it clears it in a finally covering both success and failure.
    start_capture() only reads it, checked once, before starting a new
    cycle. Not three independent flags -- there's only one decision being
    protected, three things that can hold it closed.
  - STTEngine.reload(config) already exists -- its busy_flag constructor
    param (defaults to its own threading.Event() when nothing is shared in)
    is this exact flag. The orchestrator doesn't invent it; it constructs one
    Event and passes the same instance into both STTEngine and AudioCapture.

BLOCK A -- MODEL (STTEngine.reload)
  - Download, if needed, happens as part of this same call, with its own
    progress feedback, before the reload itself runs.
  - Uses the shared flag from COMMON -- sets it before starting real
    work, clears it in a finally regardless of outcome.
  - The contrived edge case (reload while a recording is already in
    progress) is absorbed by wrapping the transcribe() call so one bad
    transcription logs one line and continues instead of ending the
    session -- now a real dependency of this design, not leftover scope.

BLOCK B -- AUDIO DEVICE (AudioCapture.rebuild)
  - Uses the shared flag from COMMON -- sets it before swapping the
    device, clears it in a finally regardless of outcome.

FATAL VS RECOVERABLE
==============================================================================
  - Orchestrator's call, no watchdog/survivor process.
  - Unrecoverable means the whole stack exits -- red error, "Unrecoverable
    error" modal, log captured to disk first (generalizing
    app._report_callback_exception's existing pattern -- native MessageBoxW,
    not Tk, since Tk itself might be compromised), a bug-report link.
  - User re-clicking the desktop icon is the accepted recovery gesture.
  - threading.excepthook gets built (cheap, catches silent
    thread-death-by-exception).
  - Every unhandled exception feeds the same path: threading.excepthook
    (background threads), the generalized app._report_callback_exception
    pattern (main thread, Tk and .after() callbacks alike), and a raw
    try/except around startup itself before Tk exists (today's
    _log_startup_crash). Three catch points, one destination.
  - The generic fatal category is called fatal, not daemon-crash -- that
    name presupposed a process split that's going away. Red, ERROR
    marker, box=True, same modal mechanism as mic-fault/model-fault.
    Concrete triggers: missing Python dependencies, any unhandled
    exception. Unlike mic-fault/model-fault, it has exactly one outcome
    -- nothing Settings can fix for either, so the modal never routes
    there. Message, bug-report link, exit.


==============================================================================
LOGGING MIGRATION
==============================================================================
  - GENERAL RULE: when a function or branch gets rewritten or removed by
    this refactor, any log() call inside it must be explicitly carried
    into whatever replaces it. Logging does not survive by default just
    because the code around it does -- check it at every site being
    touched, don't assume it follows along.
  - Survives unchanged: the CATEGORIES table, error_log()'s
    disk-write-first pattern (vdict/tray/log.py), transcript.write()'s
    dedicated logger. None of these need to change in their own
    definitions, only in how they get called.
  - The disk-write half, write_error_log in vdict/common/output.py, is
    already called directly by vdict_daemon.py. This refactor doesn't need
    to invent that cross-process bridge, it already exists.
  - At real risk: vdict_daemon.py's log() call sites all need a home in
    whatever the new thread-body version of this file looks like. Re-derive
    them by grepping the file rather than trusting a figure here.
  - session.log_session_block() currently reports the subprocess's PID
    and fires on every start/restart -- under this design a restart is
    rare (unrecoverable fault only), so this block's trigger point and
    content need redefining, not just relocating verbatim.
  - mic-fault/model-fault survive as categories, but their modal/dispatch
    bundles don't carry over as-is -- they need to match FATAL VS
    RECOVERABLE's recoverable-vs-unrecoverable split. Open for the mic-fault
    modal specifically, once the daemon no longer exits on a mic fault: does
    Close just dismiss, with the daemon already running and Settings already
    open underneath, and does MIC_FAULT_FLAG_PATH get deleted outright?
  - log()'s actual new mechanism is still the BLOCKERS item at the top --
    this section doesn't resolve that, it's why that blocker matters.
