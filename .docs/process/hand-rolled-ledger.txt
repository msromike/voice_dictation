DISAGREEMENTS BETWEEN SWEEPS -- all four CLOSED by measurement, spike-notes.txt
==============================================================================
1. SystemExit on the worker: neither. It hangs the thread and crashes the
   later shutdown. The fault channel is a signal to the GUI thread to quit.
2. Blocking waits vs event-driven capture: event-driven. A blocked thread
   receives no audio at all; the capture worker spins its own event loop
   and never blocks. wait_for_press/wait_for_release are DELETE as ruled.
3. QClipboard thread affinity: GUI thread only. Off-thread writes fail
   silently, deadlock, or wipe the clipboard. inject() runs on the GUI
   thread; transcription returns its text by signal.
4. restoreGeometry off-screen: Qt pulls the window back onto the primary
   screen. No clamp. The Pos and _clamp_to_desktop rows stand as DELETE.

Also settled by the same batch: the SetProcessDpiAwareness line in
vdict_tray.py is DELETE (pins the process below Qt's per-monitor mode);
hotkey.py's SetForegroundWindow is DELETE (activateWindow() is granted
after WM_HOTKEY); minimize-to-tray must defer hide() by one event-loop
turn; a null QAudioDevice never errors and records from the default mic,
so device validity is checked before start().
