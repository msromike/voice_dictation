VOICE DICTATION - EXTRACTION SCHEMA

Destination contract for the deterministic ETL pipeline. Data, not prose.

Every extraction row names one destination file, one bucket, and the boundary
test it satisfies. A block satisfying two boundary tests is split before it
routes -- the dry run fails a row naming more than one.

Buckets are pre-created empty, with None as the body, before any drain runs.
The injection anchor has to exist already: Python injects after it, and a
router that creates its own destination is a router generating text.


ANCHOR RULE -- RULE
  The anchor is the full header line as written, never a tag or a fragment.
  "B14" appears in prose; "B14. LOG TRANSCRIPTS TO A FILE -- REFINEMENT" does
  not. The dry run fails any anchor occurring other than exactly once.

HEADER STYLES DIFFER BY FILE, LEFT THAT WAY ON PURPOSE -- DECISION
  banner   ====== line above and below the header text.
           roadmap, backlog, defects, pre-push.
  bare     uppercase line, blank line above and below.
           spike-notes, design-decisions.
  Each file keeping its own style is part of what keeps anchors unique.
  What that beat: normalising every file to one style, which would have made
  every header collide with every other file's headers for no gain.
  Overturned if a single file ever needs both styles at once.

7  .docs/process/design-decisions.txt                        NEW FILE, bare
==============================================================================
EARNS A PLACE  A chosen implementation shape, and the alternative it beat.
               The test against spike-notes: a measurement deleted is
               re-measured to the same answer. A decision deleted does not
               re-derive -- the default regenerates the version that lost.
ENTRY SHAPE    What was chosen + what it beat + what would overturn it.
BUCKETS        THREADING AND LIFECYCLE
               CONFIG AND PERSISTENCE
               AUDIO DEVICE
               CORPUS AND SCHEMA
               ERROR HANDLING
               RETIRES WITH THE QT PORT

RETIRES WITH THE QT PORT is the filter, not an afterthought. A decision that
stops existing when Tk does lands there, so the port deletes one section
instead of auditing the whole file. Every routing into it is reported, so a
wrong call is visible rather than silent.

GATES -- RULE
==============================================================================
  No drain begins against a dirty tree. The commit before it names the
  monolith being drained. That commit is the restore point, and restoring is
  how the routing gets iterated rather than got right first time.

  manifest.db and payloads/ are gitignored. A reset to re-run must revert the
  documents and never the routing table.

  The expected extraction count is written to the database before the first
  payload is generated, by a structural pass over the source. A drain that
  ends short fails against it rather than reporting a clean table.
